# 必读声明与图文管理

客户端顶栏的“必读声明”展示免费开源声明、官方 B 站与 GitHub 链接，以及已发布的图片和附文。发行包内置初始截图，离线时也可查看。

新安装用户首次打开软件时显示免费开源提示。点击“收到，不再显示。”后，选择保存在独立的 `support-state.json` 中，不会被语言设置、战备配置或后续声明内容更新重置。已有配置或启动记录的用户升级时不会自动弹出首次提示。

## 后台操作

战备数据库顶栏新增“声明图文”入口。管理员可以添加图片与附文、编辑已有条目或删除条目，保存后静默发布。

- 支持 JPEG / PNG，上传上限 5 MiB；服务端重新编码为 JPEG，最长边限制为 1800 × 2400，单图结果上限 1 MiB。
- 最多 20 条图文，每条附文最多 500 个字符，总发布内容最多 8 MiB。
- 使用现有 Cloudflare Access 身份检查与同源请求校验，不增加管理员或客户端写入入口。
- 编辑基于当前图文版本提交；版本冲突会保留未保存的草稿。关闭并重新进入管理窗口后可载入最新版本。

## 同步与部署

声明图文使用独立的 `noticeVersion`，数据保存在既有服务数据目录的 `notices/` 子目录。不会修改战备的 `catalogVersion`，不会触发“战备数据库已更新”提示。客户端每次启动只检查一次轻量清单，版本有变化才下载图文；更新失败时继续使用本地缓存或内置截图。

公开接口为 `GET /api/v1/notices/manifest` 和 `GET /api/v1/notices/content/{version}`。后台接口为 `GET/PUT /admin/api/notices` 和 `POST /admin/api/notices/image`。

发布使用现有战备签名密钥，客户端检查固定公钥、签名、摘要、版本、路径和大小后才缓存。内容版本文件及审计记录不可变，当前清单采用原子替换。声明存储异常不会阻止原战备服务启动。

上线后台时需要一并部署 `lib/notices.mjs`、`public/notices.js`、初始 `data/resale-listing.jpg` 和更新后的 Nginx 路由。Nginx 新增 `/api/v1/notices/` 代理，并将管理员请求体上限调整为 10 MiB。保留现有数据目录和签名密钥；不要用开发密钥覆盖生产密钥。新客户端在旧后台尚未部署时仍能显示内置声明和截图。

回滚客户端或后台代码不会修改原战备数据。保留 `notices/` 和 `support-state.json`，可在重新升级后继续使用既有图文与确认状态。

## 验证

运行 `npm run check`、`npm test`。测试覆盖首次提示与升级兼容、确认保存失败、静默更新、离线回退、图片验证、签名与篡改、版本冲突、不可变历史及战备版本隔离。
